# Local setup and revival status

## Runtime

Ruby 3.4.12 (rbenv), Rails 8.1.4, PostgreSQL. The upgrade was checked incrementally
through Rails 7.1, 7.2, and 8.0 before 8.1. The application uses Mountain Time.
The existing Sprockets/Tailwind/Hotwire stack is retained; this is not a rewrite.

```sh
pwd
rbenv version
bundle install
bin/preflight
bin/dev
```

`bin/preflight` runs Ruby lint, ERB lint, the CSS build, RSpec including a
390-pixel-wide headless Chrome workflow, Brakeman, and bundler-audit. It requires
PostgreSQL, Chrome/Chromium, and network access for advisory updates. Never use
bundle update. Story-linked commits and the revival branch push are authorized. Production deployment remains excluded.

## Databases and preservation

config/database.yml defines separate development and test databases. Verify the
selected local database before running migrations. Never use a production URL.
Run `RAILS_ENV=test bundle exec rails db:migrate` for the test database only.
The schema is generated by migrations; do not edit db/schema.rb manually.

The original development database is powpals_beta_development and has not been
migrated or reset during this restoration. A read-only audit found:

- 80 duplicated resort/pass association groups.
- One account with more than one user profile.
- One duplicated account/resort/ski-day group.
- Five houses without an admin or lease-holder membership.

The new migration intentionally stops if duplicates exist. It does not choose
which identity to keep or delete records. Restoring this dataset requires a
reviewed merge plan and explicit house-manager assignments. Alternatively use
a separate local database, preserving the original intact. The development-only
POWPALS_DATABASE override makes this possible without affecting the test database:

```sh
POWPALS_DATABASE=powpals_beta_revival_development bin/setup
POWPALS_DATABASE=powpals_beta_revival_development bin/dev
```

This separate database has been created and verified and is now the development
default, so ordinary bin/setup and bin/dev use it. These commands do not copy or
delete the historical dataset. Bear Lodge history has since been restored through
the separate guarded import described in HISTORICAL_DATA.md. Select POWPALS_DATABASE=powpals_beta_development
only for a reviewed reconciliation of the historical records. No production data
or Fly resources have been accessed or changed.

## Accounts and external services

- Google login needs PP_GOOGLE_OAUTH_CLIENT_ID and PP_GOOGLE_OAUTH_CLIENT_SECRET
  with a callback matching the local host. Existing email accounts are not
  automatically linked to Google; sign in with the original method or use the
  password reset flow. OAuth identity is provider plus UID, never display name.
- Development email opens with letter_opener. New password accounts need email
  confirmation. Live Google credentials and email delivery are not verified by
  the mocked tests.
- WEATHER_API_KEY enables weather. Missing/failed/short forecasts display a dash
  without blocking the dashboard. Refreshes use the local async job adapter and
  a one-hour cache; duplicate refreshes are throttled for one minute. No Redis
  worker is needed for this local flow. HTTP responses are mocked in the test suite.
- House managers (admin or lease_holder) can edit house settings, add existing
  registered users, and manage rooms. Other members can plan their own stays;
  guests can view but cannot write stays. New houses assign their creator as
  lease holder atomically. Existing owners are never guessed from record order.
- Set rental start/end dates and capacities in Edit house. Stays validate guests,
  parking, rental bounds, and occupancy. Calendar writes lock the house row.

## Scope and remaining product work

Public friendships, messaging, meetups, bed reservations, expense integrations,
and AI features remain separate future work. The directory is informational.
Room inventory is not a bed-booking system. Production hosting, delivery,
backups, Fly deployment, and server configuration are explicitly excluded.

Do not run the historical factory-based db:seed against your existing dataset.
Keep the user's pre-existing README edits intact.
